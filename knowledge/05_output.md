# Output Format

## Definition

Output Format은 결과를 어떤 형태로 낼지 지정하는 원리다.
표, 불릿, 번호 목록, JSON, 코드블록, 문단 등 원하는 구조를 명시한다.

---

## Why

형식을 지정하지 않으면 모델이 매번 다른 구조로 답해 후속 처리가 어렵다.
특히 프로그램이 결과를 자동으로 읽어야 할 때 형식 고정은 필수다.
공식 가이드들은 원하는 출력 구조를 명시하고, 예시로 형식을 보여주라고 권장한다.

---

## When to use

- 결과를 프로그램이 자동 처리해야 할 때 (예: JSON)
- 여러 항목을 일관된 구조로 비교·나열해야 할 때 (예: 표)
- 형식 일관성이 품질에 중요한 반복 작업일 때

---

## When NOT to use

- 자유로운 서술이 더 자연스러운 대화형 답변일 때
- 형식을 과하게 강제해 내용 품질이 희생되는 경우
- 형식이 실제로 필요 없는데 습관적으로 JSON 등을 요구하는 경우

---

## Good Example

```
결과를 아래 JSON 형식으로만 출력해라. 다른 설명은 붙이지 마라.

{
  "category": "menu | order | reservation | off_topic",
  "reason": "선택 이유 한 문장"
}
```

원하는 구조와 필드가 명확해 결과를 그대로 프로그램이 읽을 수 있다.

---

## Bad Example

```
분류 결과랑 이유 알려줘.
```

왜 나쁜가:
- 결과 구조가 없어 어떤 때는 문단, 어떤 때는 목록으로 나온다.
- 자동 처리(파싱)가 불가능해 후속 작업이 깨진다.

---

## Common Mistakes

- 형식을 말로만 설명하고 실제 예시 구조를 안 보여준다.
- "JSON으로 줘"라고만 하고 필드 이름·타입을 지정하지 않는다.
- 형식 지시를 프롬프트 맨 앞에만 두고, 긴 프롬프트 끝에서 다시 강조하지 않는다.

---

## Checklist

- [ ] 원하는 출력 형식을 구체적으로 지정했는가? (예/아니오)
- [ ] 형식을 예시 구조로 보여줬는가? (필드/항목 포함)
- [ ] 자동 처리가 필요하면 필드 이름·값 범위를 정했는가?
- [ ] 프롬프트가 길면 끝에서 형식을 한 번 더 강조했는가?
