# Examples (Few-shot)

## Definition

Examples(Few-shot)는 원하는 입력-출력 쌍을 몇 개 보여줘서
모델이 그 패턴을 따라 하게 하는 원리다.
설명만으로 부족할 때 "이렇게 해라"를 실제 예시로 보여 준다.

---

## Why

말로 하는 설명보다 실제 예시가 판단 경계를 더 정확히 전달한다.
특히 형식이 까다롭거나 분류 기준이 애매한 작업에서 효과가 크다.
공식 가이드들은 먼저 예시 없이(zero-shot) 시도하고, 결과가 불안정하면 예시를 추가하라고 권장한다.

---

## When to use

- 출력 형식이 까다로워 예시로 보여줘야 할 때
- 분류·판단 기준의 경계가 애매할 때 (경계 사례를 예시로 제시)
- 특정 스타일·톤을 정확히 재현해야 할 때

---

## When NOT to use

- zero-shot(예시 없이)만으로 이미 결과가 안정적일 때. 불필요한 예시는 토큰만 늘린다.
- 예시가 한쪽으로 치우쳐 있을 때. 모델이 그 편향을 그대로 따라 한다.
- 예시가 틀렸을 때. 잘못된 예시는 잘못된 출력을 유도한다.

---

## Good Example

```
아래 예시처럼 사용자 요청을 분류해라.

"오늘 영업해요?" -> menu
"예약 취소해 주세요." -> reservation
"파이썬 코드 짜줘." -> off_topic

이제 분류: "땅콩 없는 메뉴 추천해줘."
```

정상 사례와 경계 사례(off_topic)를 함께 보여줘 판단 기준이 분명하다.

---

## Bad Example

```
알아서 잘 분류해줘.
(예시로 전부 'menu'만 3개 제시)
```

왜 나쁜가:
- 예시가 한 종류(menu)로만 치우쳐 모델이 다 menu로 분류하려 한다.
- 경계 사례가 없어 애매한 입력을 어디로 보낼지 배우지 못한다.

---

## Common Mistakes

- 예시를 정상 사례로만 채우고 경계/예외 사례를 빼먹는다.
- 예시가 실제 원하는 출력과 형식이 다르다.
- 필요 없는데도 예시를 잔뜩 넣어 프롬프트를 부풀린다.

---

## Checklist

- [ ] 예시가 필요한 작업인가? (zero-shot으로 부족한가?) (예/아니오)
- [ ] 예시에 정상 사례와 경계/예외 사례가 함께 있는가?
- [ ] 예시의 형식이 실제 원하는 출력과 일치하는가?
- [ ] 예시가 특정 답으로 치우쳐 있지 않은가?
